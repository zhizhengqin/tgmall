## 1. 项目概述

### 1.1 项目背景

柬埔寨电子商务市场正处于高速增长期。2024 年电商市场规模达 **15.1 亿美元**，同比增长 17.1%，占 GDP 的 6.68%。预计到 2029 年，电商用户将从 200 万增长至 290 万。

Telegram 在柬埔寨拥有约 **550 万活跃用户**，是仅次于 Facebook 和 TikTok 的第三大社交平台。大量本地经营者已通过 Telegram 频道和群组进行产品推广，但缺乏专业的电商功能支撑（统一支付、订单管理、物流追踪）。目前柬埔寨市场上**尚无专业的 Telegram 电商 Mini App**，这是一个明确的蓝海市场。

本项目是公司自营的 Telegram Mini App 电商平台。消费者在 Telegram 内完成浏览→加购→下单→支付的完整闭环，公司通过 Web 管理后台统一管理商品、订单和用户。

### 1.2 产品愿景

> **通过 Telegram Mini App 为柬埔寨消费者提供便捷、可信赖的购物体验。**

### 1.3 产品定位

| 维度 | 描述 |
|------|------|
| **产品类型** | 基于 Telegram Mini App 的公司自营电商平台 |
| **运营模式** | 公司统一采购、定价、发货 |
| **目标市场** | 柬埔寨（金边 → 暹粒 → 西哈努克市 → 全国） |
| **核心价值** | 零下载、Telegram 生态内闭环交易 |
| **差异化** | 社交+电商融合、Bakong/KHQR 原生支付集成、高棉语优先 |

### 1.4 项目范围

**V2 核心范围（已交付）：**

> 消费者在 Mini App 浏览→加购→下单→支付；管理员通过用户名密码登录 Web 后台管理商品/订单/用户。

**明确不做（当前阶段）：**

- ❌ 开放第三方经营
- ❌ 直播购物
- ❌ AI 智能推荐
- ❌ 社群团购
- ❌ 跨境购

```
│ 促销活动引擎 · 限时秒杀 · 会员体系              │
│ Telegram Channels 集成推广 · 数据分析后台      │
│ 商城装修 · 批量商品导入                        │
└─────────────────────────────────────────────┘

第三期（成熟期，第 10-18 个月）：生态闭环
┌─────────────────────────────────────────────┐
│ 直播购物 · 社群团购 · 跨境购                   │
│ 供应链金融 · 完整广告系统                      │
│ 自有物流体系 · 开放 API                       │
└─────────────────────────────────────────────┘
```

### 3.2 MVP 里程碑

| 里程碑 | 时间 | 标准 |
|--------|------|------|
| **M1: 地基搭建** | Sprint 1（第 5-6 周） | Telegram 登录可用；商品列表 API 跑通；Mini App 首页可展示商品 |

### 4.2 消费者端功能（Telegram Mini App）

#### F-C01: 用户注册与登录

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 消费者通过 Telegram 一键授权登录，无需额外注册 |
| **关键交互** | 打开 Mini App → 自动获取 Telegram 用户信息 → 首次使用弹出授权确认 → 登录完成 |
| **业务规则** | ① 使用 Telegram WebApp SDK 的 `initData` 进行用户身份验证；② 后端必须校验 `initData` 真实性，防止伪造；③ 手机号为选填项（下单时必填）；④ 首次登录自动创建账号，绑定 Telegram ID |

#### F-C02: 商品浏览与搜索

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 消费者可按品类浏览商品列表，支持关键词搜索和筛选排序 |
| **关键交互** | 首页品类入口 → 商品列表（瀑布流/网格）→ 下拉刷新 → 上拉加载更多 → 点击进入详情 |
| **业务规则** | ① 默认按"最新上架"排序；② 支持按价格（低→高/高→低）、销量、品类筛选；③ 搜索支持商品名称关键词（高棉语+英语+中文）；④ 商品卡片显示：主图、名称、USD/KHR 双价格 |

#### F-C03: 商品详情页

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 展示单个商品的完整信息，支持规格选择和加入购物车 |
| **关键交互** | 商品图片轮播（可放大）→ 商品名称+描述 → 规格选择（颜色/尺码等）→ 数量增减 → 加入购物车 / 立即购买 |
| **业务规则** | ① 图片支持手势放大缩小；② 多规格 SKU 需联动显示价格和库存；③ 同时显示 USD 和 KHR 价格；④ 库存为 0 时显示"售罄"，按钮灰显；⑤ 商品描述支持富文本（高棉语/英语/中文） |

#### F-C04: 购物车

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 管理待购买商品的临时列表，支持修改数量和删除 |
| **关键交互** | 查看购物车列表 → 修改数量（+/-）→ 删除商品 → 全选/单选 → 去结算 |
| **业务规则** | ① 购物车数据后端同步（因 Mini App 的 localStorage 可能不持久）；② 实时校验库存，库存不足时提示；③ 显示每项小计和合计（USD+KHR）；④ 支持优惠券选择应用 |

#### F-C05: 下单与结算

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 确认订单信息，选择支付方式，创建订单 |
| **关键交互** | 确认商品列表 → 填写/选择收货地址 → 选择支付方式（KHQR/ABA Pay/Wing Pay/COD）→ 应用优惠券 → 提交订单 |
| **业务规则** | ① 配送地址必须包含：收件人、手机号（+855 格式验证）、详细地址；② 订单金额计算：商品总价 - 优惠券抵扣 + 配送费 = 实付金额；③ 下单时扣减库存（预占）；④ 在线支付订单 15 分钟内未支付自动取消订单，释放库存 |

#### F-C06: 支付

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 通过 Telegram 原生支付或跳转完成 KHQR/ABA Pay/Wing Pay 支付 |
| **关键交互** | 选择支付方式 → KHQR：生成支付码，用户用银行 App 扫码 / ABA Pay：跳转 ABA App 支付 / Wing Pay：跳转 Wing App / COD：确认下单 |
| **业务规则** | ① 必须使用 Telegram 原生支付接口，不可自定义支付页面；② 支付回调后端校验签名；③ 支付成功后自动更新订单状态为"已付款"并发送 Bot 通知；④ 支付失败显示错误原因（高棉语/英语/中文）；⑤ 在线支付超时时间 15 分钟 |

#### F-C07: 订单中心

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 查看所有订单列表和详情，支持取消和追踪 |
| **关键交互** | 订单列表（按状态 Tab 切换）→ 点击查看订单详情 → 取消订单（待付款状态）/ 确认收货（在线支付已发货或 COD 已收款状态）/ 查看物流 |
| **业务规则** | ① 订单状态流转：在线支付：待付款 → 已付款 → 已发货 → 已完成；COD：已确认 → 已发货 → 已付款 → 已完成；均可取消至已取消。② 各状态对应可操作按钮不同；③ 物流信息实时更新（接入第三方物流 API 或手动录入）；④ 已完成订单支持查看（不可操作） |

#### F-C08: 个人中心

| 属性 | 描述 |
|------|------|
| **优先级** | P1（Should Have） |
| **描述** | 管理个人资料、收货地址、优惠券 |
| **关键交互** | 查看/编辑个人资料 → 收货地址管理（增删改）→ 我的优惠券列表 → 语言切换 |
| **业务规则** | ① 手机号验证：柬埔寨号段（+855）；② 最多保存 10 个收货地址；③ 优惠券显示使用状态（未使用/已使用/已过期） |

#### F-C09: 优惠券中心

| 属性 | 描述 |
|------|------|
| **优先级** | P1（Should Have） |
| **描述** | 浏览可领取优惠券，查看已领取的优惠券 |
| **关键交互** | 优惠券列表（可领取）→ 点击领取 → 我的优惠券 → 下单时选择使用 |
| **业务规则** | ① 支持类型：满减券、折扣券、免邮券；② 每人每种券限领 1 张；③ 优惠券有总量限制和有效期；④ 下单时自动计算最优优惠组合 |

### 4.4 公共服务

#### F-S01: Telegram Bot 通知

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 通过 Telegram Bot 向运营人员和消费者推送关键通知 |
| **通知场景** | ① **消费者**：下单成功、支付成功、已发货（含物流单号）、订单完成、优惠券即将过期；② **运营人员**：新订单提醒、买家已付款、库存预警 |
| **业务规则** | ① Bot Token 安全存储，不可泄露；② 通知内容支持多语言（根据用户语言偏好）；③ 通知失败记录日志并重试 3 次 |

#### F-S02: 多语言与本地化

| 属性 | 描述 |
|------|------|
| **优先级** | P0（Must Have） |
| **描述** | 系统全面支持高棉语、英语、中文三种语言 |

## 9. 需求优先级矩阵（MoSCoW）

### 9.1 Must Have（MVP 必须交付）

| 编号 | 功能 | 所属端 | 理由 |
|------|------|--------|------|
| F-C01 | Telegram 一键登录 | 消费者 | 无登录无法识别用户，一切功能的入口 |
| F-C02 | 商品浏览与搜索 | 消费者 | 核心购物体验起点 |
| F-C03 | 商品详情页 | 消费者 | 消费者决策关键页面 |
| F-C04 | 购物车 | 消费者 | 批量购买基础功能 |
| F-C05 | 下单结算 | 消费者 | 交易闭环核心环节 |
| F-C06 | KHQR/ABA Pay/Wing Pay 支付 | 消费者 | 收钱的核心，没有支付=没有商业模式 |
| F-C07 | 订单追踪 | 消费者 | 消费者下单后唯一关注的功能 |
| F-M01 | 商品管理 | 运营后台 | 平台自营商品供给的核心 |
| F-M02 | 订单处理 | 运营后台 | 运营日常履约核心 |
| F-S01 | Telegram Bot 通知 | 公共服务 | 连接运营人员和消费者的关键通信通道 |

## 11. 风险与假设

### 11.1 关键假设

| 假设 | 验证方法 | 如果假设不成立... |
|------|----------|-------------------|
| 柬埔寨消费者愿意在 Telegram Mini App 内购物 | 种子用户测试，观察转化漏斗 | 需加大用户教育投入，或增加 Facebook 渠道 |
| 供应商/货源能支撑平台 2-5% 毛利空间 | 供应商访谈和采购成本测算 | 调整定价策略或压缩运营成本 |
| Bakong/KHQR API 可正常对接 | Sprint 3 技术预研 | 先上 COD+手动确认，支付后补 |
| 柬埔寨 3G/4G 网络可支撑 Mini App 加载 | 真机弱网测试 | 做极简版（砍图片，纯文字列表） |
| 第三方物流 API 可对接 | 技术选型阶段验证 | 手动录入物流单号 |
| Telegram Mini App 政策无重大变化 | 持续关注官方更新 | 预留 Web App 备用方案 |

### 11.2 主要风险与对策

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| Shopee/Lazada 价格战反击 | 中 | 高 | 差异化定位，不正面竞争；聚焦社交电商和 Telegram 生态 |
| 商品采购/上架速度慢于预期 | 中 | 高 | 提前锁定种子供应商；加快选品与上架流程；先做供给端再推广消费端 |
| KHQR 支付对接遇到技术障碍 | 中 | 高 | 提前技术预研；准备 COD 为主的过渡方案 |
| Mini App 在低端机/弱网下体验差 | 高 | 中 | 从第 1 周起用真机+柬埔寨实际网络测试；严格的性能门禁 |
| 技术人才招聘困难 | 中 | 中 | 远程团队+本地团队混合模式；技术栈选择招聘容易的语言 |
| 高棉语翻译质量问题 | 中 | 中 | 雇佣本地专业翻译，不依赖机器翻译；上线前由本地人验收 |
