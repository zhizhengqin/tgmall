## 一、测试策略总览

### 1.1 测试金字塔

```
         ╱──────╲
        ╱   E2E  ╲          3 条核心流程
       ╱──────────╲
      ╱  集成测试  ╲        12 条 API 场景
     ╱──────────────╲
    ╱    单元测试     ╲      80+ 条（已 29）
   ╱──────────────────╲
```

| 层级 | 已有 | 计划 | 说明 |
|------|------|------|------|
| 单元测试 | 29 | 80+ | 后端服务函数 + 工具函数 |
| 集成测试 | 0 | 12+ | API 端点 + 数据库事务 |
| E2E | 0 | 3 | 核心交易链路 |
| 安全测试 | 0 | 5 | CSO 审计发现验证 |
| 性能测试 | 0 | 3 | 并发 + 负载 |

### 1.2 测试原则

| 原则 | 说明 |
|------|------|
| **TDD 优先** | 核心交易链路（订单/支付）必须先写测试再写代码 |
| **覆盖率 ≥ 80%** | 订单服务、支付服务、Bot 通知服务必须达到 |
| **原子提交** | 每个测试搭配对应的功能代码，同一 commit |
| **回归防护** | 每个 CSO/QA 发现的 bug 必须写回归测试 |
| **真实数据** | 测试数据模拟柬埔寨用户场景（+855 手机号、高棉语姓名） |

## 六、端到端测试（E2E）

### 6.1 核心交易闭环

```
E2E-01: 用户浏览 → 搜索商品 → 查看详情 → 加购 → 结算 → 选择地址 → 下单 → 查看订单
E2E-02: 用户下单 → KHQR 支付（模拟）→ 支付回调 → Bot 通知 → 订单状态变为 paid
E2E-03: 管理员登录后台 → 查看新订单 → 确认发货 → 用户收到发货通知 → 确认收货
E2E-04: 用户下单（COD）→ 管理员发货 → 骑手收款 → 管理员 collect-cod → 订单变为 paid → 用户确认收货
```

## 十、测试执行规范

### 10.1 命名规范

```
测试文件：{模块名}.test.js         (如 order-service.test.js)
测试用例：it('{场景描述}')          (如 it('库存不足应拒绝下单'))
测试套件：describe('{模块名} ({功能})')
```

### 10.2 提交规范

```
test: {描述}                        (新增测试)
test(qa): regression test for ISSUE-NNN (回归测试)
```

### 10.3 测试数据

```javascript
// Mock 柬埔寨用户数据
const mockUser = {
  telegramId: '123456789',
  firstName: 'សុភាព',           // 高棉语姓名

// Mock 商品数据（双币种）
```

### 10.4 运行检查清单

```bash
# 每次提交前
npm test                                           # 后端全量测试

# 每个 Sprint 结束
npm run test:unit && npm run test:integration    # 全量 + 集成
npm run build --workspace=tgmall-admin           # 管理员后台构建

# MVP 发布前
npm test -- --coverage                           # 覆盖率报告
npx playwright test                               # E2E 测试
```
