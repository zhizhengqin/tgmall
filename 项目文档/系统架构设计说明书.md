## 一、架构概述与设计原则

### 1.1 架构愿景

构建一个**低成本、高可靠、易扩展**的 Telegram Mini App 社交电商平台。首期支撑 10 万用户 + 日均 500 单（公司自营），架构预留平滑扩展至百万用户 + 万级 SKU 的能力。

### 1.2 核心设计原则

| 原则 | 说明 | 架构体现 |
|------|------|----------|
| **MVP 优先** | 先让"买卖跑起来"，复杂功能后期迭代 | 模块化设计，核心交易闭环先行，增长功能通过插件/微服务扩展 |
| **柬埔寨本地化优先** | 弱网、低端机、高棉语、KHQR 支付是硬约束 | CDN + 图片压缩 + 前端分包 + Bakong API 一等公民 |
| **安全第一** | 支付和用户数据绝对不能出事 | initData 校验 + JWT + HTTPS + PCI 合规 + 数据加密 |
| **成本可控** | 启动资金 $15 万，架构不能烧钱 | AWS 新加坡单区域起步，无 Kubernetes（先用 Docker Compose），Redis 最小规格 |
| **可观测性** | 出问题必须 5 分钟内知道 | 结构化日志 + CloudWatch 告警 + 健康检查端点 |
| **开发体验** | 柬埔寨本地招聘难，技术栈尽量统一 | JavaScript/TypeScript 全栈（Vue.js + Node.js），一套语言前后端通吃 |

### 1.3 关键架构决策（ADR）

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| **前端框架** | Vue.js vs React | **Vue.js 3** | Vue 社区在东南亚更活跃；学习曲线更平缓；Telegram Mini App 社区推荐 |
| **后端语言** | Node.js vs Python vs Go | **Node.js (Express)** | JS 全栈统一降低招聘难度；I/O 密集型电商场景 Node.js 天然优势；NPM 生态丰富 |
| **数据库** | PostgreSQL vs MySQL vs MongoDB | **PostgreSQL 15** | 关系型数据（订单/商品/用户）；JSONB 支持灵活字段（商品规格）；高棉语 Unicode 成熟；开源免费 |
| **缓存** | Redis vs Memcached | **Redis 7** | 购物车 + Session + 热点数据 + 消息队列 + 分布式锁，Redis 全覆盖 |
| **消息队列** | RabbitMQ vs Kafka vs BullMQ | **BullMQ (基于 Redis)** | MVP 阶段消息量不大；基于 Redis 无需额外运维；后期可平滑迁移到 RabbitMQ |
| **部署方式** | Kubernetes vs Docker Compose vs 裸机 | **Docker Compose（MVP）→ ECS Fargate（增长期）→ EKS（成熟期）** | 前期简单够用，避免 K8s 运维负担；AWS 托管服务平滑升级 |
| **云服务商** | AWS vs 阿里云 vs 腾讯云 | **AWS 新加坡区域** | 柬埔寨认可的数据存储地；服务成熟度最高；Free Tier 节省前期成本 |
| **文件存储** | S3 vs 本地磁盘 vs 第三方 OSS | **AWS S3 + CloudFlare CDN** | S3 标准；CloudFlare 柬埔寨有边缘节点；自动 WebP 转换 |

### 2.2 选型理由详述

#### 2.2.1 前端框架：Vue.js 3 + Vite

| 维度 | 评估 |
|------|------|
| **为什么选 Vue.js？** | ① 东南亚开发者社区活跃，柬埔寨本地招聘更容易找到 Vue 开发者；② 学习曲线比 React 平缓，适合团队快速上手；③ Composition API + `<script setup>` 语法简洁，开发效率高；④ Telegram Mini App 社区有成熟的 Vue 集成方案（`vue-tg` 等） |
| **为什么用 Vite？** | 开发服务器冷启动 < 1 秒；HMR 极快；构建产物 Tree-shaking 彻底（Mini App 包体积敏感）；原生 ESM |
| **状态管理：Pinia** | Vue 3 官方推荐，TypeScript 友好，模块化设计（userStore / cartStore / languageStore） |
| **路由：Vue Router 4** | SPA 标配，支持路由懒加载（代码分割，减少首屏体积） |
| **UI 组件** | **Mini App 端**：手写组件（包体积控制，无第三方 UI 库）；**Web 后台**：Element Plus（成熟的 Vue 3 组件库） |
| **国际化：vue-i18n** | 三语（km/en/zh）支持，Lazy Loading 语言包 |
| **Telegram SDK** | `@twa-dev/sdk` 或直接使用 `window.Telegram.WebApp` 原生对象 |

#### 2.2.2 后端框架：Node.js 20 + Express 4

| 维度 | 评估 |
|------|------|
| **为什么 Node.js？** | ① JS 全栈统一——前端 Vue、后端 Node、都用 TypeScript/JavaScript，一套语言降低团队技能要求；② I/O 密集型电商场景（API 网关、支付回调、消息推送）Node.js 事件循环天然优势；③ NPM 生态丰富：支付 SDK、Telegram Bot API、验证库等现成包；④ 柬埔寨本地 Node.js 开发者相对容易招聘 |
| **为什么 Express？** | 最成熟的 Node.js 框架；社区资源最多；中间件生态最丰富；学习成本最低 |
| **为什么不选 Nest.js？** | MVP 阶段过度设计。Nest.js 学习曲线陡峭，装饰器+依赖注入对团队有负担。Express 够用，后期可迁移 |
| **为什么不用 Python？** | Python 同样是优秀选项（FastAPI 性能好），但会选择"全栈 JS"统一技术栈，降低上下文切换成本 |
| **ORM：Prisma** | 类型安全的数据库访问；自动生成 Migration；可视化 Studio；支持 PostgreSQL 高级特性（JSONB、全文搜索） |

#### 2.2.3 数据库：PostgreSQL 15

| 维度 | 评估 |
|------|------|
| **为什么 PostgreSQL？** | ① 电商数据高度关系型（用户→订单→商品），SQL 是最优解；② JSONB 列支持灵活的商品规格（如 `{"color":"red","size":"L"}`）；③ 高棉语 Unicode 支持成熟（`UTF-8` 编码，`km_KH` Collation）；④ 全文搜索支持三语（`tsvector` + GIN 索引）；⑤ 开源免费，AWS RDS 或自建均可 |
| **为什么不 MongoDB？** | 订单/支付/优惠券等核心业务数据是强关系型，MongoDB 的事务和关联查询不如 PostgreSQL |
| **为什么不 MySQL？** | PostgreSQL 的 JSONB 和全文搜索更适合电商场景，且许可证更自由 |

#### 2.2.4 缓存与消息队列：Redis 7

| 用途 | 数据结构 | Key 设计 | TTL |
|------|----------|----------|-----|
| 购物车 | Hash | `cart:{user_id}` | 7 天（与登录态一致） |
| Session/Token 黑名单 | String | `blacklist:{token_hash}` | Token 过期时间 |
| 商品详情缓存 | String (JSON) | `product:{product_id}` | 30 分钟 |
| 商品列表缓存 | String (JSON) | `products:list:{category}:{page}:{sort}` | 5 分钟 |
| 汇率数据 | String | `exchange_rate:usd_khr` | 每日更新 |
| API Rate Limit | Sorted Set | `ratelimit:{user_id}:{endpoint}` | 滑动窗口 1 分钟 |
| 消息队列 | BullMQ (基于 Redis) | `notifications`、`payments_callback` | — |
| 分布式锁 | String (SET NX) | `lock:order:{order_id}` | 30 秒 |

### 3.2 数据流全景：一次下单的完整旅程

```javascript
import { onMounted, reactive } from 'vue'

export function useTelegram() {
  const tg = window.Telegram?.WebApp

  const state = reactive({
    isReady: false,
    user: null,
    themeParams: null,
    isDark: false,
    viewportHeight: 0
  })

  function init() {
    if (!tg) return

    tg.ready()                          // 告知 Telegram Mini App 已就绪
    tg.expand()                         // 扩展到最大可用高度

    state.isReady = true
    state.user = tg.initDataUnsafe?.user
    state.themeParams = tg.themeParams
    state.isDark = tg.colorScheme === 'dark'

    // 监听主题变化
    tg.onEvent('themeChanged', () => {
      state.isDark = tg.colorScheme === 'dark'
      applyTheme(tg.themeParams)
    })

    // 配置返回按钮
    tg.BackButton.onClick(() => {
      window.history.back()
    })

    applyTheme(tg.themeParams)
  }

  function applyTheme(params) {
    if (!params) return
    const root = document.documentElement
    root.style.setProperty('--tg-bg-color', params.bg_color || '#ffffff')
    root.style.setProperty('--tg-text-color', params.text_color || '#000000')
    root.style.setProperty('--tg-hint-color', params.hint_color || '#999999')
    root.style.setProperty('--tg-button-color', params.button_color || '#2ea6ff')
    root.style.setProperty('--tg-button-text-color', params.button_text_color || '#ffffff')
    root.style.setProperty('--tg-secondary-bg-color', params.secondary_bg_color || '#f0f0f0')
  }

  function showBackButton() {
    tg?.BackButton.show()
  }

  function hideBackButton() {
    tg?.BackButton.hide()
  }

  onMounted(() => init())

  return { tg, state, showBackButton, hideBackButton }
}
```

### 4.4 API 请求层封装

```javascript
// src/api/index.js
import axios from 'axios'
import { useUserStore } from '@/stores/userStore'

const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'https://api.shop.xinhua-tech.kh',
  timeout: 10000,
  headers: { 'Content-Type': 'application/json' }
})

// 请求拦截器 —— 自动附加 JWT + 语言头
apiClient.interceptors.request.use((config) => {
  const userStore = useUserStore()
  if (userStore.token) {
    config.headers.Authorization = `Bearer ${userStore.token}`
  }
  config.headers['Accept-Language'] = userStore.language || 'km'
  return config
})

// 响应拦截器 —— 统一错误处理 + Token 刷新
let isRefreshing = false
let failedQueue = []

apiClient.interceptors.response.use(
  (response) => response.data,
  async (error) => {
    const originalRequest = error.config

    // Token 过期 → 自动刷新
    if (error.response?.status === 401 && !originalRequest._retry) {
      if (isRefreshing) {
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject })
        }).then(token => {
          originalRequest.headers.Authorization = `Bearer ${token}`
          return apiClient(originalRequest)
        })
      }

      originalRequest._retry = true
      isRefreshing = true

      try {
        const token = await refreshToken()
        failedQueue.forEach(({ resolve }) => resolve(token))
        failedQueue = []
        originalRequest.headers.Authorization = `Bearer ${token}`
        return apiClient(originalRequest)
      } catch (refreshError) {
        failedQueue.forEach(({ reject }) => reject(refreshError))
        failedQueue = []
        useUserStore().logout()
        return Promise.reject(refreshError)
      } finally {
        isRefreshing = false
      }
    }

    // 统一错误提示
    const message = error.response?.data?.message || 'network_error'
    return Promise.reject({ ...error, userMessage: message })
  }
)

export default apiClient
```

### 4.5 包体积优化策略

| 策略 | 实现 | 预期效果 |
|------|------|----------|
| **路由懒加载** | Vue Router `() => import(...)` | 首屏 JS < 500KB |
| **语言包按需加载** | `vue-i18n` Lazy Loading | 初始只加载默认语言（~15KB） |
| **图片懒加载** | Intersection Observer + `<img loading="lazy">` | 首屏图片请求减少 70% |
| **WebP 格式** | CDN 自适应 + `<picture>` 标签 | 图片体积减少 40% |
| **Tree Shaking** | Vite Rollup 自动 | 未使用代码不进入构建产物 |
| **Gzip/Brotli** | Nginx 开启静态压缩 | 传输体积减少 60% |
| **第三方库最小化** | 不用 Element Plus（Mini App 端手写组件） | 省 ~200KB |
| **字体 Subset** | Noto Sans Khmer Subset（仅常用字） | 字体从 300KB → 50KB |

### 5.4 订单服务核心伪代码

```javascript
// src/services/order.service.js
async function createOrder(userId, orderData) {
  const { items, shippingAddressId, couponId, paymentMethod } = orderData

  // 1. 获取分布式锁（防同一用户并发下单）
  const lockKey = `lock:order:${userId}`
  const lock = await redis.set(lockKey, '1', 'NX', 'EX', 30)

  // 2. 使用 Prisma 交互式事务
  const order = await prisma.$transaction(async (tx) => {
    // 2a. 逐商品校验库存（行锁 SELECT ... FOR UPDATE）
    for (const item of items) {
      const product = await tx.$queryRaw`
        SELECT stock, price_usd, price_khr
        FROM products WHERE id = ${item.productId} FOR UPDATE
      `
      if (product.stock < item.quantity) {
        throw new InsufficientStockError(product.name, product.stock)
      }
    }

    // 2b. 计算价格（以数据库价格为准，不信任前端传入）
    let totalUsd = 0, totalKhr = 0
    for (const item of items) {
      const product = await tx.product.findUnique({ where: { id: item.productId } })
      totalUsd += product.priceUsd * item.quantity
      totalKhr += product.priceKhr * item.quantity
    }

    // 2c. 校验并应用优惠券
    let discountUsd = 0
    if (couponId) {
      const coupon = await tx.userCoupon.findFirst({
        where: { userId, couponId, status: 'unused' },
        include: { coupon: true }
      })
      if (!coupon || coupon.coupon.endDate < new Date() || totalUsd < coupon.coupon.minSpend) {
        throw new InvalidCouponError()
      }
      // 标记优惠券已使用
      await tx.userCoupon.update({
        where: { id: coupon.id },
        data: { status: 'used', usedAt: new Date() }
      })
      discountUsd = coupon.coupon.type === 'fixed'
        ? coupon.coupon.value
        : Math.round(totalUsd * coupon.coupon.value / 100 * 100) / 100
    }

    // 2d. 预扣库存
    for (const item of items) {
      await tx.product.update({
        where: { id: item.productId },
        data: { stock: { decrement: item.quantity } }
      })
    }

    // 2e. 创建订单
    const order = await tx.order.create({
      data: {
        userId,
        // 公司自营模式：订单由平台统一管理
        totalUsd: totalUsd - discountUsd,
        totalKhr: totalKhr - Math.round(discountUsd * exchangeRate),
        status: paymentMethod === 'cod' ? 'paid' : 'pending_payment',
        paymentMethod,
        shippingAddressId,
        couponId,
        paymentTimeout: new Date(Date.now() + 15 * 60 * 1000),
        items: {
          create: items.map(item => ({
            productId: item.productId,
            quantity: item.quantity,
            priceUsd: item.priceUsd,   // 当时价格（快照）
            priceKhr: item.priceKhr,
            spec: item.spec || {}
          }))
        }
      }
    })

    return order
  })

  // 3. 释放锁
  await redis.del(lockKey)

  // 4. 清除购物车缓存
  await redis.del(`cart:${userId}`)

  // 5. 异步发送通知
  await notificationQueue.add('order_created', {
    orderId: order.id,
    userId
  })

  return order
}
```

### 8.2 支付回调统一处理

```javascript
// src/services/payment.service.js

// 支付回调统一入口
// POST /api/v1/webhooks/payment
async function handlePaymentCallback(payload, provider) {
  const { orderNumber, transactionId, status, signature } = payload

  // 1. 验签 —— 防伪造回调
  const isValid = verifySignature(payload, signature, provider)
  if (!isValid) throw new InvalidSignatureError()

  // 2. 幂等检查 —— 防重复回调
  const idempotencyKey = `payment:callback:${provider}:${transactionId}`
  const isDuplicate = await redis.get(idempotencyKey)
  if (isDuplicate) {
    logger.warn({ orderNumber, transactionId }, 'Duplicate payment callback ignored')
    return { status: 'duplicate' }
  }
  await redis.set(idempotencyKey, '1', 'EX', 86400) // 24h

  // 3. 查询订单
  const order = await prisma.order.findUnique({ where: { orderNumber } })
  if (!order) throw new OrderNotFoundError()

  // 4. 更新订单状态
  if (status === 'success') {
    await prisma.order.update({
      where: { id: order.id },
      data: {
        paymentStatus: 'success',
        status: 'paid',
        paidAt: new Date()
      }
    })

    // 5. 加入通知队列
    await notificationQueue.add('payment_success', {
      orderId: order.id,
      userId: order.userId
    })
  } else {
    await prisma.order.update({
      where: { id: order.id },
      data: { paymentStatus: 'failed' }
    })
  }

  return { status: 'processed' }
}
```

### 10.2 initData 校验流程

```javascript
// src/integrations/telegram.js
const crypto = require('crypto')

function verifyInitData(initData, botToken) {
  // 1. 解析 initData 字符串
  const params = new URLSearchParams(initData)
  const hash = params.get('hash')
  params.delete('hash')

  // 2. 按 key 字母序排序并拼接
  const dataCheckString = Array.from(params.entries())
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([k, v]) => `${k}=${v}`)
    .join('\n')

  // 3. 使用 Bot Token 对 data_check_string 计算 HMAC-SHA256
  const secretKey = crypto.createHmac('sha256', 'WebAppData')
    .update(botToken)
    .digest()

  const computedHash = crypto.createHmac('sha256', secretKey)
    .update(dataCheckString)
    .digest('hex')

  // 4. 比较 hash
  if (computedHash !== hash) {
    throw new InvalidInitDataError('Signature mismatch')
  }

  // 5. 检查 auth_date 时效（24h）
  const authDate = parseInt(params.get('auth_date'), 10)
  const now = Math.floor(Date.now() / 1000)
  if (now - authDate > 86400) {
    throw new InvalidInitDataError('auth_date expired')
  }

  // 6. 解析用户信息
  const user = JSON.parse(params.get('user') || '{}')
  return {
    telegramId: user.id,
    firstName: user.first_name,
    lastName: user.last_name,
    username: user.username,
    languageCode: user.language_code
  }
}
```

| **必须 HTTPS** | Mini App URL 必须是 `https://` | 全站强制 HTTPS，Nginx SSL 终止 |
| **localStorage 不持久** | Telegram 可能随时清除 WebView 数据 | 购物车后端同步 (Redis)；Token 过期自动刷新 |
| **支付必须走 TG 原生** | Mini App 内不能自定义支付页面 | `WebApp.openInvoice` / 跳转 Bank App Deep Link |
| **返回按钮** | 用户会用物理返回按钮 | `WebApp.BackButton.onClick` 处理页面栈 |
| **主题适配** | 必须响应亮色/暗色主题 | `WebApp.themeParams` → CSS 变量 |
| **包体积** | 大包在弱网打不开 | 路由懒加载 + 图片 CDN + WebP |
| **无外部浏览器** | Mini App 在 Telegram 内嵌 WebView 运行 | 所有链接使用 `WebApp.openLink` |
| **initData 校验** | 任何人都可以伪造 | 后端 HMAC-SHA256 强制校验 |
| **6.0 版本事件处理** | Telegram 6.0+ 事件处理方式不同 | 使用 SDK 封装层隔离版本差异 |

### 14.2 Mini App 生命周期管理

```
用户点击 Bot 菜单按钮
        │
        ▼
  Telegram 加载 Mini App URL (iframe/WebView)
        │
        ▼
  Vue.js App 启动
        │
        ├── main.js: 调用 Telegram.WebApp.ready()
        │                   告知 Telegram "Mini App 已就绪"
        │
        ├── router: 根据用户状态导航
        │   ├── 未登录 → 显示登录授权页
        │   └── 已登录 → 首页
        │
        ├── composables/useTelegram.js:
        │   ├── WebApp.expand() — 扩展到全屏
        │   ├── WebApp.enableClosingConfirmation() — 开启关闭确认
        │   ├── WebApp.BackButton.onClick(handleBack)
        │   └── WebApp.onEvent('themeChanged', handleTheme)
        │
        └── 用户关闭 Mini App (上滑/X 按钮)
            └── Telegram 可能销毁 WebView
                └── Vue App 被销毁
                    └── Pinia 状态丢失（购物车已同步到后端）
```

### 14.3 离线与弱网处理策略

```
网络状态监听 (navigator.onLine + 请求超时)
        │
        ├── 在线 ───► 正常模式 (API 直连 + CDN 图片)
        │
        ├── 弱网 (请求 > 3s 未响应)
        │   ├── 显示骨架屏 (Skeleton)
        │   ├── 图片渐进式加载 (占位图 → 低清 → 高清)
        │   └── 自动重试 (最多 3 次，间隔递增 1s/3s/5s)
        │
        └── 离线 (navigator.onLine === false)
            ├── 显示离线提示页（非白屏）
            ├── 展示提示："请检查网络连接" (三语)
            └── 提供"重试"按钮 (恢复网络后重新加载)
```
