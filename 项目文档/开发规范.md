## 一、总则

### 1.1 核心原则

> **代码是写给人看的，顺便能在机器上运行。**

| 原则 | 说明 |
|------|------|
| **可读性优先** | 代码读的次数远多于写的次数。命名清晰比注释多更重要。 |
| **一致性第一** | 无论团队谁的代码，风格必须一致。看起来像同一个人写的。 |
| **自动化强制执行** | ESLint、Prettier、Commitlint 在 CI 中自动检查。人工审查只关注逻辑。 |
| **渐进式严格** | MVP 阶段不必追求 100% 测试覆盖率，但核心交易链路必须 ≥ 80%。 |

### 1.2 适用范围

本规范适用于 TG Mall 项目所有代码仓库：

| 仓库 | 说明 | 技术栈 |
|------|------|--------|
| `tgmall-miniapp` | 消费者端 Telegram Mini App | Vue.js 3 + Vite |
| `tgmall-admin` | 平台运营 Web 后台 | Vue.js 3 + Vite + Element Plus |
| `tgmall-api` | 后端 API 服务 | Node.js + Express + Prisma |

### 1.3 工具链总览

| 工具 | 用途 | 配置文件 |
|------|------|----------|
| **ESLint** | JavaScript/TypeScript 代码检查 | `.eslintrc.cjs` |
| **Prettier** | 代码格式化 | `.prettierrc` |
| **Commitlint** | Git 提交信息检查 | `commitlint.config.js` |
| **Husky** | Git Hooks（Pre-commit + Commit-msg） | `.husky/` |
| **lint-staged** | 仅检查暂存文件（加速 Pre-commit） | `package.json` → `lint-staged` |
| **Vitest / Jest** | 单元测试 + 集成测试 | `vitest.config.js` / `jest.config.js` |

## 二、Git 工作流与分支策略

### 2.1 分支模型

```
main                      生产分支（受保护，禁止直接 Push）
  │
  ├── dev                  开发主线（受保护，禁止直接 Push）
  │     │
  │     ├── feature/*      功能分支（从 dev 切出，合并回 dev）
  │     ├── fix/*          缺陷修复分支
  │     └── hotfix/*       紧急修复分支（从 main 切出，合并回 main + dev）
  │
  └── release/*            发布分支（从 dev 切出，合并回 main + dev）
```

### 2.2 分支命名规范

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| 功能分支 | `feature/<短描述>` | `feature/khqr-payment` |
| 修复分支 | `fix/<短描述>` | `fix/cart-stock-validation` |
| 紧急修复 | `hotfix/<短描述>` | `hotfix/payment-callback-500` |
| 发布分支 | `release/v<版本号>` | `release/v1.0.0` |

**命名要求**：
- 全部小写，单词用连字符 `-` 分隔
- 描述简洁，2-4 个单词
- 用英文描述功能，不用中文（Git 命令行兼容性）
- 示例：✅ `feature/admin-product-import` ❌ `feature/导入商品功能_v2_final`

### 2.3 分支操作流程

```
// === 开始新功能 ===
git checkout dev
git pull origin dev
git checkout -b feature/khqr-payment

// === 开发过程中，定期同步 dev ===
git checkout dev
git pull origin dev
git checkout feature/khqr-payment
git merge dev                  // 或 git rebase dev（保持历史线性）

// === 功能完成，提交 PR ===
git push origin feature/khqr-payment
// → 在 GitHub/GitLab 创建 Pull Request，目标分支 dev
// → 至少 1 人 Code Review 通过
// → CI 流水线全部通过
// → 合并到 dev（使用 Squash Merge 或 Merge Commit，禁止 Fast-Forward）

// === 合并后清理 ===
git branch -d feature/khqr-payment    // 删除本地分支
git push origin --delete feature/khqr-payment  // 删除远程分支
```

### 2.4 分支保护规则

| 分支 | 直接 Push | PR 必须 Review | CI 必须通过 | 要求 |
|------|-----------|---------------|-------------|------|
| `main` | ❌ 禁止 | ✅ ≥ 1 人 | ✅ 全部通过 | 仅通过 PR 合并，合并后自动部署 Production |
| `dev` | ❌ 禁止 | ✅ ≥ 1 人 | ✅ 全部通过 | 仅通过 PR 合并，合并后自动部署 Staging |
| `feature/*` | ✅ 允许 | — | — | 命名必须符合规范 |
| `hotfix/*` | ✅ 允许 | ✅ ≥ 2 人 | ✅ 全部通过 | 从 main 切出，合并回 main + dev |

## 三、提交信息规范（Conventional Commits）

### 3.1 格式

```
<type>(<scope>): <简短描述>

<详细描述 — 可选>

<关联 Issue — 可选>
```

### 3.2 Type 类型

| Type | 说明 | 使用场景 |
|------|------|----------|
| `feat` | 新功能 | 新增用户故事、新页面、新 API |
| `fix` | 缺陷修复 | 修 Bug |
| `docs` | 文档变更 | 只改 README、注释、PRD 文档 |
| `style` | 代码风格 | 格式化、空格、分号（不影响逻辑） |
| `refactor` | 重构 | 改代码结构但不改功能 |
| `perf` | 性能优化 | 数据库查询优化、前端包体积减小 |
| `test` | 测试 | 新增或修改测试用例 |
| `chore` | 杂项 | CI 配置、依赖更新、构建脚本 |
| `revert` | 回滚 | 撤销之前的提交 |

### 3.3 Scope 范围

| Scope | 说明 |
|-------|------|
| `auth` | 登录与认证 |
| `product` | 商品模块 |
| `cart` | 购物车 |
| `order` | 订单模块 |
| `payment` | 支付模块 |
| `platform` | 平台自营/店铺配置 |
| `coupon` | 优惠券 |
| `notify` | 消息通知 |
| `admin` | 运营后台 |
| `i18n` | 多语言 |
| `ci` | CI/CD 流水线 |
| `db` | 数据库 |
| `mini-app` | Mini App 前端 |
| `api` | 后端 API |

### 3.4 示例

```bash
# ✅ 好的提交信息
git commit -m "feat(payment): 集成 Bakong KHQR 支付二维码生成"

git commit -m "fix(cart): 修复结算时库存校验未考虑多规格的问题

当商品有多个规格时，库存校验只检查了基础库存而未检查当前选中规格的库存。
现在会遍历 orderItems 中的每个 spec，匹配 products.specs JSONB 中对应规格的库存。

Closes #42"

git commit -m "refactor(order): 将订单创建逻辑提取为独立 Service

从 order.controller.js 中提取 createOrder 到 order.service.js，
便于单元测试和复用。"

git commit -m "chore(ci): 配置 GitHub Actions 自动部署 Staging"

# ❌ 不好的提交信息
git commit -m "修复了一个bug"
git commit -m "WIP"
git commit -m "更新代码"
git commit -m "."
```

```javascript

    'subject-max-length': [2, 'always', 72],
```

## 四、代码风格规范

### 4.1 通用规则

| 规则 | 约定 | 原因 |
|------|------|------|
| **缩进** | 2 个空格（禁止 Tab） | 全团队统一，`.editorconfig` 强制 |
| **换行符** | LF（`\n`），禁止 CRLF | Git 跨平台兼容 |
| **行尾空格** | 全部删除 | Prettier 自动处理 |
| **文件末尾空行** | 必须有一个空行 | POSIX 标准 |
| **行宽上限** | 100 字符 | Prettier 配置 `printWidth: 100` |
| **引号** | 单引号 `'` | JS 社区惯例，Prettier 统一 |
| **分号** | 必须有 | 防止 ASI 陷阱，ESLint 强制 |
| **尾逗号** | 全部加（trailing commas） | 减少 Git Diff，Prettier 统一 |

### 4.2 EditorConfig

```ini

charset = utf-8

indent_size = 2
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

## 五、命名规范

### 5.1 通用命名对照表

| 对象 | 命名风格 | 示例 | 说明 |
|------|----------|------|------|
| **文件名（JS/TS）** | kebab-case | `order-service.js`、`use-cart.js` | 小写+连字符 |
| **文件名（Vue 组件）** | PascalCase | `ProductCard.vue`、`OrderList.vue` | 大驼峰 |
| **CSS 类名** | kebab-case 或 BEM | `.product-card`、`.cart__item--soldout` | 小写+连字符 |
| **JavaScript 变量** | camelCase | `userName`、`totalPrice` | 小驼峰 |
| **JavaScript 常量** | UPPER_SNAKE_CASE | `MAX_ADDRESS_COUNT`、`API_BASE_URL` | 全大写+下划线 |
| **JavaScript 函数** | camelCase，动词开头 | `getUserById()`、`createOrder()` | 小驼峰+动词前缀 |
| **JavaScript 类** | PascalCase | `OrderService`、`PaymentGateway` | 大驼峰 |
| **Vue 组件名** | PascalCase，多个单词 | `ProductCard`、`OrderDetail` | 必须 ≥ 2 个单词，避免与 HTML 标签冲突 |
| **数据库表名** | snake_case，复数 | `users`、`order_items` | 小写+下划线 |
| **数据库列名** | snake_case | `telegram_id`、`created_at` | 小写+下划线 |
| **API 端点** | kebab-case | `/admin-orders`、`/order-items` | 小写+连字符 |
| **Git 分支** | kebab-case | `feature/khqr-payment` | 小写+连字符 |

### 5.2 函数命名动词前缀

| 前缀 | 含义 | 示例 |
|------|------|------|
| `get` | 获取单个/列表 | `getUserById()`、`getProductList()` |
| `create` | 创建新记录 | `createOrder()` |
| `update` | 更新已有记录 | `updateProduct()` |
| `delete` / `remove` | 删除记录 | `deleteAddress()`、`removeCartItem()` |
| `find` | 查找（可能返回 null） | `findUserByPhone()` |
| `fetch` | 异步获取 | `fetchOrderDetail()` |
| `check` / `is` / `has` | 返回布尔值 | `isLoggedIn()`、`hasStock()` |
| `handle` | 事件处理 | `handleSubmit()`、`handlePaymentCallback()` |
| `validate` | 校验 | `validatePhone()` |
| `format` | 格式化 | `formatPrice()`、`formatDate()` |
| `convert` | 转换 | `convertUsdToKhr()` |
| `generate` | 生成 | `generateOrderNumber()` |

### 5.3 布尔变量命名

```javascript
// ✅ 正确：is/has/can/should 开头，读起来像一个判断题
const isLoggedIn = true;
const hasAddress = false;
const canCancel = order.status === 'pending_payment';
const shouldRefresh = Date.now() - lastFetch > 60000;
const isOutOfStock = product.stock === 0;
const isDefault = address.isDefault;

// ❌ 错误：看不出是布尔值
const logged = true;           // → isLoggedIn
const address = false;         // → hasAddress
const stock = false;           // → isOutOfStock
```

### 5.4 禁止的命名

| 禁止 | 原因 | 替代 |
|------|------|------|
| 单字母变量（除 `i`、`j` 循环外） | 无意义 | `index`、`item`、`user` |
| 拼音命名 | 非中文团队成员看不懂 | 英文单词 |
| 数字/特殊字符开头 | 语法问题 | 字母开头 |
| `data`、`info`、`temp` | 太泛泛 | 具体描述 |
| `data2`、`newData`、`old` | 通过版本号区分 | 更具体的名称 |
| `flag` | 不知道什么 flag | `isReady`、`hasError` |

### 6.4 Composables 使用规范

```javascript
// ✅ 好的 Composable：单一职责，返回清晰
// composables/useCart.js
import { ref, computed } from 'vue';
import { useCartStore } from '@/stores/cartStore';

export function useCart() {
  const cartStore = useCartStore();
  const isAdding = ref(false);

  const itemCount = computed(() => cartStore.items.length);

  const totalUsd = computed(() =>
    cartStore.items.reduce((sum, item) => sum + item.priceUsd * item.quantity, 0)
  );

  async function addToCart(productId, quantity) {
    isAdding.value = true;
    try {
      await cartStore.addItem(productId, quantity);
    } finally {
      isAdding.value = false;
    }
  }

  return { isAdding, itemCount, totalUsd, addToCart };
}
```

### 6.5 禁止事项

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| ❌ 直接操作 DOM（`document.querySelector`） | 绕过 Vue 响应式 | 使用 `ref` + `$refs` |
| ❌ 在 `v-for` 中用 `index` 做 `key` | 列表重排时性能差且可能出错 | 用唯一 ID |
| ❌ 修改 Props | Props 是单向数据流 | 用 `emit` 通知父组件 |
| ❌ `watch` 深度监听大对象 | 性能差 | 只 watch 需要的具体属性 |
| ❌ 未清理的定时器/事件监听 | 内存泄漏 | `onUnmounted` 中清理 |
| ❌ 巨型组件（> 300 行） | 难以维护 | 拆分子组件 + Composable |
| ❌ 在模板中写复杂表达式 | 难以阅读 | 提取为 computed |

### 6.6 Telegram Mini App 特有规范

```vue
// color: var(--tg-text-color);
```

### 7.3 服务层（Service）规范

```javascript
// services/product.service.js
import prisma from '../config/database.js';
import redis from '../config/redis.js';

/**
 * 获取商品列表（含缓存）
 * @param {Object} options - 查询参数
 * @param {number} options.page - 页码
 * @param {number} options.limit - 每页数量
 * @param {string} [options.category] - 品类筛选
 * @param {string} [options.q] - 搜索关键词
 * @param {string} [options.sort] - 排序方式
 * @param {string} [options.language] - 返回语言
 * @returns {Promise<{items: Array, total: number, ...}>}
 */
export async function listProducts({ page, limit, category, q, sort, language = 'km' }) {
  // 1. 构建查询条件
  const where = {
    status: 'active',
    stock: { gt: 0 }
  };

  if (category) {
    where.category = category;
  }

  if (q) {
    // 多语言搜索：用 OR 连接三个语言字段
    where.OR = [
      { nameKm: { contains: q, mode: 'insensitive' } },
      { nameEn: { contains: q, mode: 'insensitive' } },
      { nameZh: { contains: q, mode: 'insensitive' } }
    ];
  }

  // 2. 确定排序
  let orderBy;
  switch (sort) {
    case 'price_asc':  orderBy = { priceUsd: 'asc' };  break;
    case 'price_desc': orderBy = { priceUsd: 'desc' }; break;
    default:           orderBy = { createdAt: 'desc' };  // newest
  }

  // 3. 查询数据库
  const [items, total] = await Promise.all([
    prisma.product.findMany({
      where,
      orderBy,
      skip: (page - 1) * limit,
      take: limit,
      select: {
        id: true,
        // 同时返回三语名称字段，由展示层根据用户语言选择
        nameKm: true,
        nameEn: true,
        nameZh: true,
        priceUsd: true,
        priceKhr: true,
        images: true    // 取第一张图做缩略图
      }
    }),
    prisma.product.count({ where })
  ]);

  // 4. 返回结果
  return {
    items,
    total,
    page,
    limit,
    totalPages: Math.ceil(total / limit),
    hasNext: page * limit < total
  };
}
```

```javascript
export class AppError extends Error {
  constructor(message, statusCode, errorCode) {
    super(message);
    this.statusCode = statusCode;     // HTTP 状态码
    this.errorCode = errorCode;       // 业务错误码（如 INSUFFICIENT_STOCK）
    this.isOperational = true;        // 标记为可预期的业务错误
    Error.captureStackTrace(this, this.constructor);
  }
}

// middleware/error-handler.js —— 全局错误处理中间件
export function errorHandler(err, req, res, _next) {
  // 记录错误日志
  logger.error({
    message: err.message,
    stack: err.stack,
    requestId: req.id,
    path: req.path,
    method: req.method
  });

  // 区分可预期错误 vs 不可预期错误
  if (err.isOperational) {
    // 业务错误：返回友好的错误消息（三语）
    return res.status(err.statusCode).json({
      success: false,
      error: {
        code: err.errorCode,
        message: getLocalizedMessage(err.errorCode, req.headers['accept-language'])
      }
    });
  }

  // 未知错误：返回 500，不泄露内部细节
  return res.status(500).json({
    success: false,
    error: {
      code: 'INTERNAL_ERROR',
      message: getLocalizedMessage('INTERNAL_ERROR', req.headers['accept-language'])
    }
  });
```

### 8.4 事务使用规范

```javascript
// ✅ 需要事务的场景：涉及多表写操作 + 数据一致性要求
// 场景：创建订单（扣库存 + 创建订单 + 创建 order_items + 标记优惠券已用）

const order = await prisma.$transaction(async (tx) => {
  // 所有操作在同一个事务中，全部成功或全部回滚

  // 1. 扣库存（使用行锁）
  for (const item of items) {
    const product = await tx.product.update({
      where: { id: item.productId },
      data: { stock: { decrement: item.quantity } }
    });
    // 库存不够时抛异常 → 事务回滚
    if (product.stock < 0) {
      throw new AppError('库存不足', 400, 'INSUFFICIENT_STOCK');
    }
  }

  // 2. 创建订单
  const order = await tx.order.create({ data: orderData });

  // 3. 创建 order_items
  await tx.orderItem.createMany({ data: orderItemsData });

  // 4. 标记优惠券已用（couponId 是优惠券模板 ID，需先查到当前用户的券记录）
  if (couponId) {
    const userCoupon = await tx.userCoupon.findFirst({
      where: { userId, couponId, status: 'unused' }
    });
    if (!userCoupon) {
      throw new InvalidCouponError();
    }
    await tx.userCoupon.update({
      where: { id: userCoupon.id },
      data: { status: 'used', usedAt: new Date() }
    });
  }

  return order;
});

// ⚠️ 事务注意事项
// - 事务尽量短（不要在事务中发网络请求、写文件）
// - 事务中避免用户交互（等待用户输入）
```

### 12.1 输入校验

```javascript
// ✅ 所有用户输入必须校验（后端必须做，前端校验只是 UX 优化）

// 1. 使用 Zod 做白名单校验（只允许已知的安全输入）

// 2. 文件上传必须限制类型和大小

  allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
```

### 12.2 敏感数据处理

```javascript
// ❌ 绝对禁止
console.log(user);                    // 不能记录完整用户对象（可能含手机号）
logger.info('支付回调', payload);       // 不能记录完整支付回调（可能含密钥）
res.json(error);                      // 不能直接返回原始错误（可能含数据库结构）
throw new Error(dbError.message);     // 不能暴露数据库错误消息

// ✅ 正确做法
logger.info('用户登录', { userId: user.id });           // 只记录 ID
logger.info('支付回调成功', { orderNumber });            // 只记录订单号
res.status(500).json({ error: { code: 'INTERNAL_ERROR' } });
throw new AppError('服务器内部错误', 500, 'INTERNAL_ERROR');
```

### 12.3 禁止的代码模式

```javascript
// ❌ eval —— 永远禁止
eval('console.log("hello")');

// ❌ 动态 require/import（用户输入拼接路径）
const module = require(userInput);    // 路径遍历风险

// ❌ 密码/密钥硬编码在代码中

// ✅ 从环境变量读取
const apiKey = process.env.API_KEY;

// ❌ 用户输入直接拼接到 HTML（XSS）
element.innerHTML = userInput;
// ✅ 使用 Vue 的 {{ }} 自动转义

// ❌ 用户输入直接拼接到 SQL
const query = `SELECT * FROM users WHERE username = '${userInput}'`;
// ✅ 使用 Prisma 类型安全查询
const user = await prisma.user.findFirst({ where: { username: userInput } });
```

### 12.4 Webhook 安全

```javascript
// ❌ 绝对不能：未配置密钥时默认放行回调
if (!secret) {
  console.warn('密钥未配置，默认放行');
  return true;  // 致命错误！攻击者可伪造回调
}

// ✅ 正确做法：未配置密钥时拒绝回调
if (!secret) {
  console.error('密钥未配置，拒绝回调');
  return false;
}
```

Webhook 签名验证必须满足：
1. 密钥未配置时**拒绝**（绝不放行）
2. 使用 `crypto.timingSafeEqual` 防止时序攻击
3. 同一笔交易使用 Redis 幂等键防重复处理
4. 支付回调必须放在数据库事务中执行

### 12.5 速率限制

```javascript
// ✅ 所有生产环境必须配置全局速率限制
import rateLimit from 'express-rate-limit';

  windowMs: 15 * 60 * 1000,  // 15 分钟窗口

  legacyHeaders: false,

// 认证接口额外限制

  windowMs: 15 * 60 * 1000,
```
