# TG Mall 演示数据部署指南

> **适用场景**：在 Railway 生产数据库中填充演示数据，用于客户演示。  
> **执行人**：拥有 Railway 项目访问权限和数据库公网连接的管理员。  
> **最后更新**：2026 年 7 月 6 日

---

## 一、前置条件

1. 已安装 Node.js 和 npm
2. 已克隆 `zhizhengqin/tgmall` 仓库，并进入 `tgmall-api` 目录
3. 已安装依赖：`npm install`
4. 已从 Railway dashboard 获取到 **公网** PostgreSQL URL（形如 `postgresql://postgres:xxx@xxx.proxy.rlwy.net:xxx/railway`）

> ⚠️ 注意：Railway 默认的 `DATABASE_URL` 使用内网主机名 `postgres.railway.internal`，**无法从本地直接连接**。必须使用公网 proxy URL。

## 二、当前数据库状态说明

当前生产数据库存在以下迁移漂移：

1. **迁移 `20260701195004_add_shop_config_tables` 执行到一半失败**

   `schema.prisma` 中已定义，但对应 migration 未成功应用到生产库。演示数据 seed 脚本需要这两个字段。

## 五、常见问题

### Q1：`migrate deploy` 报错 "column already exists"

说明还有其他字段也预先存在。根据报错信息，手动执行 `ADD COLUMN IF NOT EXISTS` 补全该字段，然后重新运行 `npx prisma migrate deploy`。

### Q2：seed 报 "Can't reach database server"

说明你用的是 Railway 内网 URL（`postgres.railway.internal`）。请从 Railway dashboard 复制公网 proxy URL，通常域名以 `.proxy.rlwy.net` 结尾。

### Q3：重复运行 seed 会重复插入数据吗？

不会。seed 脚本使用 `upsert` 和唯一约束检查，幂等安全，可重复运行。

### Q4：演示数据太多了，想清空重来？

目前脚本不会自动删除数据。如需重置，需要手动 truncate 相关表，或重新创建数据库后再运行 seed。

## 六、安全提示

- 本指南中的 `DATABASE_URL` 包含数据库密码，**不要提交到 Git**
- 操作完成后，建议从终端历史记录中清除该 URL：

```bash
history -c
```

- 如果怀疑 URL 泄露，可在 Railway dashboard 中重置 PostgreSQL 密码
