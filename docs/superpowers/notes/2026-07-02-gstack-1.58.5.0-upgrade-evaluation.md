## 2. 各版本主要变更（按 TG Mall 相关度排序）

### 2.1 v1.58.5.0 — 首次运行引导 + 顶层路由优化

**核心变化**：
- 首次安装 gstack 后，bare `gstack` 命令不再显示一堆浏览器/QA 文档，而是根据仓库状态自动推荐下一步（空仓库 → 规划，有代码 → `/qa`，有未合并分支 → `/review` 再 `/ship`）。
- `/office-hours` 结尾会主动询问是否启动下一轮 review，而不是列出选项等你重打。
- 顶层 `gstack` skill 变成纯路由，浏览器/QA 内容只保留在 `/browse` 中。

**对 TG Mall 影响**：**低**。我们已经有固定工作流（`/office-hours` → `/autoplan` → 开发 → `/review` → `/ship`），不依赖 bare `gstack` 入口。`/office-hours` 主动推荐下一轮 review 算是小体验改进。

### 2.2 v1.58.4.0 — 社区 Bug 修复 + 安全守卫改为 fail-closed

**核心变化**：
- **4 个安全守卫从“失败时放行”改为“失败时阻断”**：`/ship` 的 pre-push 敏感信息扫描现在遇到 git 失败或 diff 算不出来时会**拒绝推送**，而不是静默跳过。
- 敏感信息 redaction 引擎新增 6 种凭证类型：GitLab、HuggingFace、npm、DigitalOcean、Bearer、GCP Service Account。
- `/plan-eng-review` 和 `/plan-design-review` 会先问“要 review 什么”（分支 diff / 粘贴的计划 / 具体路径），再开始审计。
- `/ship` 默认自动安装 pre-push guard。

**对 TG Mall 影响**：**高**。我们明确使用 `/ship` 和 `/cso`，安全相关变更直接相关；plan review 的 Ask-first 也能避免空跑大仓库。

### 2.3 v1.58.0.0 — 文档支持 Mermaid / Excalidraw + 多格式导出

**核心变化**：
- `/diagram` skill：用英文描述流程，返回 `.mmd` 源码 + `.excalidraw` + SVG/PNG。
- `make-pdf` 支持 ` ```mermaid ` 和 ` ```excalidraw ` 代码块渲染为矢量图。
- `make-pdf` 新增 `--to html` 和 `--to docx` 输出，HTML 为单文件、零网络请求。
- 图片本地路径自动内联，远程图片默认 blocked（需 `--allow-network`）。

**对 TG Mall 影响**：**中**。如果未来需要把架构图/流程图写进 `项目文档/`，`make-pdf` 会非常有用；目前主要用 Markdown，不是刚需。

### 2.4 v1.57.10.0 — Codex 交叉模型审查默认开启

**核心变化**：
- 新增全局开关 `codex_reviews`（默认 `enabled`），统一控制 `/review`、`/ship`、`/autoplan`、`/document-release` 和四个 `/plan-*-review` 是否调用 Codex 做交叉审查。
- 之前只有 `/review` 和 `/ship` 自动跑 Codex；plan review 每次都要手动确认；`/document-release` 不跑。
- 检测逻辑从“是否安装 codex”升级为“是否安装 + 是否登录”，未登录时降级为 Claude subagent 并给出原因。

**对 TG Mall 影响**：**中-高**。我们使用 `/review`、`/ship`、`/plan-eng-review`、`/document-release`，升级后会自动获得第二模型视角。但如果你**没有配置 Codex**或**不想额外消耗 token**，需要注意这个默认行为。

### 2.5 v1.57.6.0 — 安全守卫 fail-closed 修复

**核心变化**：
- 修复 8 个社区报告的高优先级 bug，其中 4 个是安全相关守卫“失败时放行”的问题。
- telemetry `error_message` 在离机前经过 redaction。
- `/ship` pre-push guard 在 git 失败时拒绝推送。

**对 TG Mall 影响**：**高**。与 v1.58.4.0 的 pre-push guard 改进一脉相承，是安全相关修复。

### 2.6 v1.57.5.0 — 跨会话决策记忆（Cross-session decision memory）

**核心变化**：
- 新增 `gstack-decision-log` 和 `gstack-decision-search` 命令。
- `/plan-ceo-review`、`/plan-eng-review`、`/spec`、`/ship` 会自动记录关键决策到 `~/.gstack/projects/<slug>/decisions.jsonl`。
- 新会话启动时会自动展示与当前分支/问题相关的活跃决策。
- 不依赖 gbrain，纯文件实现。

**对 TG Mall 影响**：**中**。长期使用下能减少重复讨论已敲定的架构/范围决策，但目前项目处于早期文档阶段，收益有限。

### 2.7 v1.57.0.0 — `/cso`、`/document-release`、`/design-consultation` 骨架化（carve）

**核心变化**：
- 把三个大 skill 拆成“常驻骨架 + 按需加载章节”，首次调用时少读约 49KB（~12K tokens）。
- `/cso` 的模式分发和误报过滤规则保持常驻，确保安全审计不会漏规则。

**对 TG Mall 影响**：**中**。我们使用 `/cso` 和 `/document-release`，升级后首次调用会更快、更省上下文。

### 2.8 v1.56.1.0 — `/sync-gbrain` 数据丢失修复

**核心变化**：
- 修复 `/sync-gbrain` 可能 `rm -rf` 整个仓库根目录的严重 bug。
- 清理 staging 目录前现在会验证所有权（5 重检查）。

**对 TG Mall 影响**：**低**。TG Mall 目前**没有使用 gbrain**，所以不直接相关。但如果你未来启用 gbrain，这个修复非常关键。

## 4. 用法差异

### 4.1 对 TG Mall 日常使用的影响

- **命令入口不变**：`/office-hours`、`/autoplan`、`/review`、`/cso`、`/ship` 等调用方式完全相同。
- **`/ship` 可能首次运行自动安装 pre-push guard**：v1.58.4.0 后，`/ship` 会在你同意（或已 opt-in）后自动安装 pre-push hook，扫描敏感信息。这是好事，但第一次运行时会有额外提示。
- **Plan review 会先问范围**：`/plan-eng-review` 和 `/plan-design-review` 不再直接全仓库扫描，而是先让你确认 review 目标。
- **可能自动调用 Codex**：如果本地安装了 Codex 且已登录，`/review`、`/ship`、`/autoplan`、`/plan-eng-review`、`/document-release` 会自动触发 Codex 交叉审查；未登录则降级为 Claude subagent。
- **决策自动记录**：`/plan-*-review`、`/spec`、`/ship` 会自动把关键决策写入 `~/.gstack/projects/telegrammall/decisions.jsonl`。

### 4.2 不需要改项目文件

- 不需要改 `CLAUDE.md`、不需要改 `项目文档/`、不需要改代码。
- gbrain 相关功能（v1.57.5.0、v1.57.9.0、v1.58.4.0 的 gbrain 修复）对未启用 gbrain 的团队无影响。

## 5. 升级评估

### 5.1 升级收益

| 收益 | 评估 |
|------|------|
| 安全相关 bug 修复（pre-push guard fail-closed、redaction 增强） | **高**。直接降低 `/ship` 时敏感信息泄露风险。 |
| `/cso`、`/document-release` 省 token | **中**。每次调用少读 ~12K tokens，长会话更从容。 |
| 交叉模型审查默认开启 | **中-高**。自动获得 Codex 第二意见；但如果没 Codex，只是多一行提示。 |
| 跨会话决策记忆 | **中**。长期项目收益明显，当前早期阶段收益有限。 |
| 文档多格式/Mermaid 渲染 | **中**。未来写架构文档/发布说明时有用，目前非刚需。 |
| 首次运行引导优化 | **低**。不影响已有用户。 |

### 5.2 升级风险

| 风险 | 评估 |
|------|------|
| 命令行为变化 | **低**。入口和流程基本一致，只有 plan review 先问范围、`/ship` 自动装 guard。 |
| Codex 自动调用产生额外费用 | **中**。如果已安装 Codex 并登录，会在更多路径自动调用。可用 `gstack-config set codex_reviews disabled` 一键关闭。 |
| 破坏性变更 | **无**。没有移除命令或重命名参数。 |
| 需要改项目文件 | **无**。 |

### 5.3 建议

**建议升级，优先级中高。**

理由：
1. v1.58.4.0 的 **pre-push guard fail-closed** 和敏感信息 redaction 增强对支付/电商项目很重要（安全红线）。
2. v1.57.6.0 / v1.58.4.0 修复了多个安全守卫“失败时放行”的问题，避免 `/cso` 和 `/ship` 在异常情况下漏检。
3. 对 TG Mall 现有工作流**完全兼容**，不需要改任何项目文件。
4. Codex 审查默认开启是双刃剑：有 Codex 则自动更强，没有则降级为 Claude subagent，不会坏。
5. 唯一需要留意的是 `/ship` 可能第一次运行时提示安装 pre-push hook，按提示同意即可。

**最佳升级时机**：建议在完成当前大任务（如 PRD/Backlog 文档整理）后、进入下一个开发冲刺前升级。不要在 `/ship` 中途或关键 review 进行到一半时升级。

## 6. 如何升级（供参考）

gstack 是通过 git clone 到 `~/.claude/skills/gstack` 安装的，升级步骤：

```bash
cd ~/.claude/skills/gstack
git fetch origin
git reset --hard origin/main
bun run build
```

**注意**：如果未来使用 gbrain，升级后需要再运行一次 `gstack-config gbrain-refresh`（目前 TG Mall 未使用 gbrain，可忽略）。

升级后，**新开一个 Claude Code 会话**即可使用 1.58.5.0 的技能。当前运行中的会话仍停留在 1.56.0.0。

验证版本：
```bash
cat ~/.claude/skills/gstack/VERSION
# 应输出 1.58.5.0
```

## 7. 结论

| 维度 | 结论 |
|------|------|
| 是否必须升级 | **否**，但强烈建议 |
| 是否推荐升级 | **是**，优先级中高 |
| 最佳升级时机 | 当前文档整理任务完成后、下轮开发冲刺前 |
| 升级后需改项目文件 | 不需要 |
| 主要收益 | 安全守卫更可靠、省 token、自动跨模型审查、决策记忆 |
| 主要风险 | `/ship` 首次可能提示安装 hook；Codex 自动调用可能产生额外费用（可一键关闭） |
| 对 TG Mall 现有工作流影响 | 极小，入口和命令用法不变 |
